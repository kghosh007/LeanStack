Hardware-Aligned Engineering

Silicon-Level Linux Auto-Tuning

Most hosting stacks treat Linux like a black box. LeanStack probes CPU microarchitecture, L2 cache boundaries, and storage classes during boot to tune kernel parameters for zero memory contention.

⚡

CPU L2 Cache Line Fitting

Stock MySQL sets sort/join buffers to 16MB. When 50 queries execute concurrently, buffers overflow CPU L2 cache into main DRAM, stalling execution by 200x. LeanStack pins buffers to 256KB, fitting 100% inside CPU L2 cache registers.

✔ 0.04% L2 cache miss rate
🛑

Transparent Huge Pages Lockout

Linux Transparent Huge Pages (THP) cause unpredictable 50ms memory compaction latency spikes in MariaDB and Valkey. LeanStack disables THP at boot via sysctl and systemd, eliminating random latency stalls.

✔ Zero compaction stalls
📦

ZRAM zstd In-Memory Swap

Standard disk swap wears out NVMe SSDs and causes extreme I/O freezes. LeanStack provisions compressed in-memory swap using Zstandard (zstd), compressing memory at 3:1 in RAM with zero disk wear or OOM killer crashes.

✔ 3x RAM compressibility
🚀

BBR & TCP Fast Open (Level 3)

Enables Google BBR congestion control and TCP Fast Open (TFO=3) for both incoming and outgoing client connections, cutting handshake latency in half over lossy cellular and high-latency edge connections.

✔ Sub-millisecond roundtrips

Self-Healing Guardrails & Zero-Panic Reliability

Hosting failure is usually caused by bad tenant configs, unconstrained in-memory caches, or thundering cron jobs. LeanStack automates fault containment at every layer.

🛡

Inotify Config Rollback

If a client writes a broken rewrite rule into their custom Nginx slot, ls-gatekeeper and ls-nginx-linter catch the error before reloading Angie. Bad syntax never hits production.

✔ Zero configuration crashes
🔒

Valkey 10% RAM Guard

Object caches without hard caps can explode under viral traffic and trigger kernel OOM kills. LeanStack caps Valkey strictly at 10% host RAM with allkeys-lru eviction.

✔ Guaranteed OOM immunity
⏱

Anti-Thundering Mutex

Background cron queue (ls-cron-queue) uses atomic file mutexes (flock) and hard timeouts, stopping overlapping WP-CLI cron jobs from melting CPU.

✔ Zero cron stampedes

NVMe O_DIRECT Crash Safety

MariaDB InnoDB flushes directly via O_DIRECT, bypassing the OS page cache entirely. Eliminates double-buffering and guarantees ACID transaction durability on hard reboot.

Hardened WordPress Runtime

In-House Cron Queue & Physical RSS Memory Telemetry

Visitor-triggered wp-cron is permanently eliminated. Uploads directories are locked down, and physical memory is measured straight from Linux /proc/[pid]/status.

⏱

Anti-Thundering Cron Queue

Visitor-triggered wp-cron.php is disabled globally (DISABLE_WP_CRON = true). A systemd timer dispatches serialized WP-CLI jobs with atomic flock mutexes, stopping overlapping cron storms.

✔ 0ms visitor wait latency
🔒

POSIX Sandboxing & Uploads Lock

Every site runs under its own Linux POSIX user with strict open_basedir. wp-config.php is locked with chmod 600. PHP execution in /wp-content/uploads/ is hard blocked with deny all; return 403;.

✔ Complete upload exploit immunity
📊

Real-Time In-Dashboard Telemetry

Inside WordPress Admin (Tools > LeanStack Cache), operators inspect real-time FastCGI disk size, OPcache hit rates, APCu key counts, and physical RSS process memory read directly from /proc/[pid]/status.

✔ Zero mystery load

Honest Limitations Where We Lag

What’s Lagging & Lacking

  • ✖
    No Browser Web GUI (CLI-Only): LeanStack is decoupled and CLI/API-driven (lsctl). If your clients require a point-and-click browser panel with phpMyAdmin buttons or drag-and-drop file managers, LeanStack is NOT for you today (a standalone micro-GUI is scheduled for Phase 4).
  • ✖
    Single-Node Focus (No Clustering): LeanStack is engineered for extreme density on single bare-metal or cloud instances. We do not provide automated multi-node Redis clusters, Galera database clustering, or cross-region failover out of the box.
  • ✖
    No Apache or .htaccess Support: Strictly opinionated on Angie HTTP/3 + MariaDB. If you run legacy plugins requiring Apache runtime rewrites or LiteSpeed modules, they must be converted to Angie config or run elsewhere.
  • ✖
    Hardware & OS Scope: Strictly certified on Ubuntu 22.04, 24.04 & 26.04 (x86_64). We have not validated ARM64 (aarch64) or Debian yet, so we do not claim certification on them.
  • ✖
    Manual DNS Outside Cloudflare: Automated DNS synchronization is built for Cloudflare API v4. AWS Route 53, Namecheap, or custom BIND nameservers require manual record configuration.
Transparent trade-offs for extreme density
